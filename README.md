# بک‌اند Node.js — پامیر روغن

## ⚠️ یک نکته‌ی مهم که قبلاً نادیده گرفته بودم

سرویس‌های رایگان مثل Render، فضای ذخیره‌سازی «موقتی» (ephemeral) دارند — یعنی هر بار سرویس رایگان بعد از ۱۵ دقیقه بی‌استفاده‌بودن بخوابد و دوباره بیدار شود، یا هر بار دوباره دیپلوی کنید، **فایل‌هایی که برنامه روی دیسک نوشته پاک می‌شوند**. برای همین، دیگر کافی نیست فقط سرور Node.js را دیپلوی کنید — باید داده را در یک **پایگاه‌داده‌ی واقعی و همیشگی** (MongoDB Atlas، رایگان برای همیشه) نگه دارید، نه در یک فایل ساده.

خبر خوب: این‌بار خودم این بخش را هم آماده کردم؛ شما فقط باید یک حساب رایگان MongoDB Atlas بسازید (۵ دقیقه، فقط کلیک).

## بخش مهم: راه‌اندازی «همگام‌سازی مشترک و دائمی» برای pamir_oil_app.html

اگر هدفتان فقط حل مشکل «وقتی لینک را به کامپیوتر دیگر می‌فرستم، اطلاعات خالی است» است، فقط همین بخش کافیست — نیازی به کل APIهای مدل‌شده (admins/agents/...) که در `API.md` توضیح داده شده ندارید.

سه مرحله: **ساخت پایگاه‌داده (MongoDB Atlas)** → **دیپلوی سرور (Render)** → **وصل‌کردن فایل HTML**.

### مرحله ۱ — ساخت پایگاه‌داده‌ی رایگان و همیشگی (MongoDB Atlas)

1. به [mongodb.com/cloud/atlas/register](https://www.mongodb.com/cloud/atlas/register) بروید و یک حساب رایگان بسازید.
2. در مرحله‌ی ساخت اولین Cluster، گزینه‌ی **M0 Free** را انتخاب کنید (رایگان برای همیشه، نیازی به کارت بانکی هم نیست).
3. یک نام کاربری و رمز عبور برای دیتابیس بسازید (این را جایی یادداشت کنید — «Database User»، نه رمز حساب Atlas خودتان).
4. در بخش **Network Access**، روی **Add IP Address** بزنید و گزینه‌ی **Allow Access from Anywhere** (یعنی `0.0.0.0/0`) را انتخاب کنید — چون Render از یک IP ثابت وصل نمی‌شود.
5. بعد از ساخته‌شدن Cluster (۱-۳ دقیقه)، روی دکمه‌ی **Connect** → **Drivers** بزنید. یک رشته‌ی اتصال (Connection String) به این شکل می‌بینید:
   ```
   mongodb+srv://USERNAME:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
   این را کپی کنید و `PASSWORD` را با رمزی که در مرحله‌ی ۳ ساختید جایگزین کنید. این رشته را برای مرحله‌ی بعد نگه دارید.

### مرحله ۲ — دیپلوی سرور روی Render (رایگان)

1. فایل‌های این پوشه (`backend-nodejs`) را در یک ریپازیتوری گیت‌هاب بگذارید (می‌توانید همان ریپوی `pamir-oil` را استفاده کنید، در یک پوشه‌ی جدا مثلاً `api/`).
2. در [render.com](https://render.com) با گیت‌هاب ثبت‌نام کنید.
3. New → Web Service → ریپوی خود را انتخاب کنید.
4. تنظیمات:
   - Root Directory: `backend-nodejs` (یا مسیر پوشه‌ای که آپلود کردید)
   - Build Command: `npm install`
   - Start Command: `node server.js`
   - Plan: **Free**
5. در بخش Environment Variables این‌ها را اضافه کنید:
   - `MONGODB_URI` = همان رشته‌ی اتصالی که از MongoDB Atlas کپی کردید (مرحله ۱)
   - `APP_SECRET` = یک رشته‌ی تصادفی که خودتان انتخاب می‌کنید (این کلید محرمانه‌ی سینک شماست، آن را جایی یادداشت کنید)
   - `JWT_SECRET` = یک رشته تصادفی بلند (فقط برای APIهای دیگر لازم است، برای سینک ساده هم بگذارید مشکلی نیست)
6. Deploy بزنید. بعد از چند دقیقه یک آدرس مثل این می‌گیرید:
   ```
   https://pamir-oil-api.onrender.com
   ```

### مرحله ۳ — وصل‌کردن فایل HTML به این سرور

داخل فایل `pamir_oil_app.html`، این دو خط را در ابتدای بخش اسکریپت پیدا کنید:

```js
const CLOUD_SYNC_URL='';
const CLOUD_SYNC_SECRET='';
```

و پرشان کنید:

```js
const CLOUD_SYNC_URL='https://pamir-oil-api.onrender.com/api/state';
const CLOUD_SYNC_SECRET='همان APP_SECRET که در Render گذاشتید';
```

فایل را ذخیره کنید و روی گیت‌هاب جایگزین نسخه‌ی قبلی کنید (همان روش قبلی: ویرایش `index.html` یا آپلود دوباره).

### از این به بعد چه اتفاقی می‌افتد؟

- هر تغییری (نماینده جدید، سفارش، پرداخت، تنظیمات) هم در همان مرورگر و هم روی MongoDB Atlas ذخیره می‌شود — این‌بار **واقعاً دائمی**، حتی وقتی سرور Render بخوابد یا دوباره دیپلوی شود.
- وقتی لینک را از هر دستگاه دیگری باز کنید، برنامه اول از این سرور آخرین اطلاعات را می‌گیرد — نه از صفر شروع می‌کند.
- ⚠️ این یک سینک ساده است، نه یک سیستم چندکاربره‌ی همزمان واقعی: اگر دو نفر **دقیقاً همزمان** روی دو دستگاه مختلف تغییری بدهند، آخرین ذخیره‌سازی، ذخیره‌سازی قبلی را جایگزین می‌کند. برای دیدن آخرین تغییرات یک نفر دیگر، کافیست صفحه را رفرش کنید.
- پلن رایگان Render بعد از ۱۵ دقیقه بی‌استفاده‌بودن می‌خوابد و اولین درخواست بعدی ۳۰-۵۰ ثانیه طول می‌کشد — طبیعی است، فقط چند ثانیه صبر کنید. (خود MongoDB Atlas نمی‌خوابد، همیشه در دسترس است.)
- محدودیت رایگان MongoDB Atlas: ۵۱۲ مگابایت فضا — برای داده‌ی متنی این پروژه (بدون فایل حجیم) سال‌ها کافی است.

## نصب محلی (برای توسعه/تست)

اگر `MONGODB_URI` را تنظیم نکنید، سرور به‌طور خودکار از یک فایل محلی (`db.json`) استفاده می‌کند — این فقط برای تست روی کامپیوتر خودتان مناسب است، **نه برای استفاده‌ی واقعی روی Render** (چون طبق توضیح بالا پاک می‌شود).

```bash
cd backend-nodejs
npm install
cp .env.example .env
```

سپس رمز سوپر ادمین را هش کنید و در `.env` بگذارید:

```bash
node hash-password.js "600300"
# خروجی را در SUPERADMIN_PASSWORD_HASH داخل .env قرار دهید
```

داده‌های اولیه (ادمین/نماینده پیش‌فرض) را بسازید:

```bash
npm run seed
```

سرور را اجرا کنید:

```bash
npm start
# روی http://localhost:4000 بالا می‌آید
```

## تست سریع با curl

```bash
curl -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"1234"}'
```

جزئیات کامل مسیرها در `../API.md` است.

## نکات فنی
- ذخیره‌سازی «بلاک کامل داده» (مسیر `/api/state`، همانی که به `pamir_oil_app.html` وصل است): MongoDB Atlas از طریق `mongoState.js` — واقعاً دائمی. اگر `MONGODB_URI` تنظیم نشود، به فایل محلی (`db.json` با `lowdb`) برمی‌گردد که فقط برای تست محلی مناسب است.
- ذخیره‌سازی APIهای مدل‌شده (admins/agents/orders/payments که در `API.md` توضیح داده شده‌اند): همچنان از `lowdb` (فایل محلی) استفاده می‌کنند. این APIها به `pamir_oil_app.html` وصل نیستند و برای توسعه‌ی احتمالی یک اپ جداگانه در آینده‌اند؛ اگر می‌خواهید این‌ها را هم روی Render رایگان به‌صورت دائمی استفاده کنید، باید همین‌ها را هم به MongoDB مهاجرت دهیم — کافی است بگویید.
- رمزها با `bcryptjs` هش می‌شوند.
- احراز هویت با JWT (`jsonwebtoken`)، اعتبار توکن ۱۲ ساعت.
